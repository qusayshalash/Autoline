# رفع AutoLine على سيرفر (Hostinger KVM 2)

دليل خطوة بخطوة، من سيرفر فارغ إلى موقع يعمل على دومينك ومعه بياناتك.
الوقت المتوقّع: حوالي ساعة في المرة الأولى.

> **قاعدة واحدة طوال الدليل:** كلمات المرور تكتبها أنت فقط، في نافذتك. لا ترسلها لأحد، ولا تضعها في ملف داخل المشروع.

---

## ما الذي سيعمل على السيرفر

| الجزء | ما يفعله |
|---|---|
| **web** (Caddy) | يعرض الموقع، ويحصل على شهادة HTTPS مجانية ويجدّدها وحده، ويمرّر طلبات `/api` إلى الـ backend |
| **backend** (Python + DuckDB) | الأداة نفسها. قاعدة البيانات داخله، فلا يوجد شيء آخر لتثبيته |

البيانات في مجلّد على السيرفر نفسه: `/srv/autoline/data`، والنسخ الاحتياطية في `/srv/autoline/backups`.
الكود في `/opt/autoline`. تحديث الكود لا يمسّ البيانات أبدًا.

---

## 1. شراء السيرفر

في Hostinger اختر:

| الإعداد | القيمة |
|---|---|
| الخطة | **KVM 2** (رام 8 جيجا) |
| الموقع | أوروبا: فرنسا أو ليتوانيا أو ألمانيا |
| نظام التشغيل | **Ubuntu 24.04** عادي، بدون لوحة تحكم وبدون تطبيقات |
| كلمة مرور root | قوية، واحفظها عندك |

بعد التفعيل خذ من لوحة Hostinger **عنوان السيرفر (IP)**، مثل `203.0.113.10`.

## 2. ربط الدومين (إن كان عندك دومين)

في إعدادات الـ DNS للدومين أضف سجلًّا واحدًا:

| النوع | الاسم | القيمة |
|---|---|---|
| `A` | `@` (أو اسم فرعي مثل `app`) | عنوان السيرفر IP |

قد يستغرق انتشاره من دقائق إلى ساعة. تحقّق من ويندوز:

```bash
nslookup yourdomain.com
```

يجب أن يظهر عنوان السيرفر.

> **إن استخدمت Cloudflare:** اجعل السحابة **رمادية (DNS only)** لا برتقالية. Cloudflare المجانية ترفض أي رفع أكبر من 100 ميجا، وملفّك 800 ميجا.

**بدون دومين؟** تستطيع التجربة على الـ IP مباشرة (انظر الخطوة 5)، لكن الاتصال يكون غير مشفّر، فلا تعتمد عليه للاستخدام الحقيقي.

## 3. الدخول إلى السيرفر

من ويندوز افتح **PowerShell** واكتب (ضع عنوان سيرفرك):

```bash
ssh root@203.0.113.10
```

أجب `yes` على السؤال الأول، ثم اكتب كلمة مرور root (لا تظهر الحروف أثناء الكتابة، هذا طبيعي).
كل الأوامر التالية تُكتب داخل هذه النافذة، على السيرفر.

## 4. تجهيز السيرفر (مرة واحدة)

**تحديث النظام:**

```bash
apt update && DEBIAN_FRONTEND=noninteractive apt upgrade -y
```

**الجدار الناري:** يسمح فقط بالدخول (SSH) والموقع (80 و443):

```bash
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp && ufw --force enable
```

**ذاكرة احتياطية (swap) 4 جيجا:** تحمي من توقّف الأداة إن امتلأت الرام أثناء استيراد ملف ضخم:

```bash
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**تثبيت Docker:**

```bash
curl -fsSL https://get.docker.com | sh
```

**مجلّدات البيانات** (المالك `1000` هو المستخدم الذي تعمل به الأداة داخل Docker):

```bash
mkdir -p /srv/autoline/data /srv/autoline/backups && chown -R 1000:1000 /srv/autoline
```

**تنزيل الكود:**

```bash
git clone https://github.com/qusayshalash/Autoline.git /opt/autoline
```

## 5. الإعداد

```bash
cd /opt/autoline/deploy && cp .env.example .env && nano .env
```

غيّر سطرين فقط:

```
SITE_ADDRESS=yourdomain.com
PUBLIC_ORIGIN=https://yourdomain.com
```

**بدون دومين** (تجربة على الـ IP):

```
SITE_ADDRESS=:80
PUBLIC_ORIGIN=http://203.0.113.10
```

وإن أردت صور الكتالوج لاحقًا، ضع في `CATALOG_PHOTO_CONTACT` عنوان موقعك أو بريدًا تختاره.

احفظ في nano بـ `Ctrl+O` ثم `Enter`، واخرج بـ `Ctrl+X`.

## 6. التشغيل

```bash
cd /opt/autoline/deploy && docker compose up -d --build
```

المرة الأولى تأخذ 3 إلى 5 دقائق (يبني الواجهة ويثبّت المكتبات). بعدها:

```bash
docker compose ps
```

يجب أن يظهر `backend` بحالة `healthy` و`web` بحالة `running`.

**كلمة مرور المدير الأول:** تُولَّد مرة واحدة وتُطبع في السجل:

```bash
docker compose logs backend | grep bootstrap
```

افتح `https://yourdomain.com` وادخل بـ `admin` وهذه الكلمة. إن كنت ستنقل بياناتك (الخطوة التالية) فهذا الحساب مؤقّت، لأن الاستعادة تعيد حساباتك القديمة.

## 7. نقل بياناتك من جهازك إلى السيرفر

الطريقة: نسخة احتياطية على جهازك ← تُنسخ إلى السيرفر ← زرّ «استعادة» في الموقع.

**أ. على جهازك:** شغّل الأداة محليًا، ومن **الإعدادات ← النسخ الاحتياطية** اضغط «خذ نسخة الآن»، وانتظر حتى تُعلَّم **موثّقة**.
تجدها في `C:\CSVStudioData\backups\` بمجلّد اسمه تاريخ ووقت، مثل `2026-10-28_201500`.

**ب. من PowerShell على جهازك** (نافذة جديدة، ليست نافذة السيرفر):

```bash
scp -r "C:\CSVStudioData\backups\2026-10-28_201500" root@203.0.113.10:/srv/autoline/backups/
```

حوالي 300 ميجا، فيأخذ دقائق حسب سرعة الإنترنت عندك.

**ج. على السيرفر:** أعد ملكية الملفات المنقولة للأداة:

```bash
chown -R 1000:1000 /srv/autoline/backups
```

**د. في الموقع:** **الإعدادات ← النسخ الاحتياطية**. ستظهر النسخة في القائمة. اضغط **استعادة** وأكّد.
بعد انتهائها ستخرج من الحساب، وتدخل بحسابك القديم وكلمة مرورك القديمة. كل ملفّاتك ومستخدميك وصلاحياتك كما كانت.

## 8. تحديث الموقع لاحقًا

حين تصل نسخة جديدة إلى GitHub:

```bash
bash /opt/autoline/deploy/update.sh
```

يسحب الكود الجديد ويعيد البناء والتشغيل. البيانات لا تُمسّ. يُستحسن أخذ نسخة احتياطية قبل أي تحديث كبير.

## أوامر مفيدة

كلّها من داخل `/opt/autoline/deploy`:

| الأمر | ماذا يفعل |
|---|---|
| `docker compose ps` | حالة الخدمتين |
| `docker compose logs -f backend` | سجلّ الأداة مباشرةً (اخرج بـ `Ctrl+C`) |
| `docker compose logs -f web` | سجلّ الموقع والشهادة |
| `docker compose restart backend` | إعادة تشغيل الأداة |
| `docker compose down` | إيقاف كل شيء (البيانات تبقى) |
| `docker compose up -d` | تشغيل من جديد |
| `df -h /srv` | المساحة المتبقية على القرص |

## النسخ الاحتياطية: انتبه لهذه النقطة

النسخ الاحتياطية التلقائية تُحفظ في `/srv/autoline/backups`، أي **على نفس السيرفر**. تحميك من خطأ في التنظيف أو حذف ملف بالخطأ، لكن **لا تحميك إن ضاع السيرفر نفسه**.
لذلك انسخ أحدثها إلى جهازك بين فترة وأخرى، من PowerShell على جهازك:

```bash
scp -r root@203.0.113.10:/srv/autoline/backups "C:\AutolineServerBackups"
```

## إن حدثت مشكلة

| العَرَض | السبب الغالب |
|---|---|
| الموقع لا يفتح أبدًا | الدومين لم ينتشر بعد، أو المنفذان 80/443 مغلقان في جدار Hostinger الناري من لوحة التحكم |
| `web` يعمل لكن لا شهادة HTTPS | `docker compose logs web` سيذكر السبب، وغالبًا الدومين لا يشير إلى هذا السيرفر بعد |
| تسجيل الدخول لا يفعل شيئًا | `PUBLIC_ORIGIN` لا يطابق العنوان في المتصفح حرفيًّا (https مقابل http، أو www) |
| `backend` ليس `healthy` | `docker compose logs backend`، وغالبًا مجلّد البيانات ليس ملك `1000`: أعد أمر `chown` من الخطوة 4 |
| النسخة المنقولة لا تظهر في الإعدادات | أمر `chown` في الخطوة 7ج لم يُنفَّذ، أو نُسخ المجلّد داخل مجلّد آخر |
